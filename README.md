# Арена переговоров

Тренажёр переговоров для молодых специалистов и сотрудников проектных команд. Пользователь выбирает или настраивает сценарий, ведёт диалог с LLM-собеседником и после диалога получает разбор по методике: SPIN, Гарвардский метод, BATNA или свободный режим.

Проект команды «Магнит инноваций» для задачи №9 ЛЦТ-2026 (ОЭЗ «Алабуга»).

## Как устроено

- Перед диалогом пользователь видит бриф: ситуацию, свою роль, цель, альтернативу и предмет торга. Собеседник открывает разговор первой репликой из карточки сценария; если её нет, реплику пишет LLM, без LLM — шаблон со стартовой позицией собеседника.
- После каждой реплики LLM размечает ход пользователя: вопрос об интересах, объективный критерий, конкретное предложение, давление и т. д.
- Разметка двигает скрытые счётчики собеседника: доверие, готовность уступить, раздражение. Уступает собеседник или нет, решают счётчики, LLM только формулирует ответ. Одинаковые ходы дают одинаковый исход.
- После диалога судья-LLM ставит оценки 0–100 по осям выбранного метода и разбирает 2–3 ключевых момента.
- Если LLM недоступна, тренажёр работает на правилах: разметка по маркерам, ответы по шаблонам, разбор по доле приёмов метода.
- Любую сессию можно переиграть с выбранного хода: состояние собеседника пересчитывается по сохранённой разметке, без LLM.
- Собеседник не уступает словами больше, чем разрешили правила: числа в его ответе проверяются по текущей позиции.
- У собеседника есть вымышленные имя и фамилия (поле «Имя собеседника»): подпись у его реплик, над сценой аватара и в брифе; LLM получает имя и может назвать его, если спросят. Без имени показывается роль. Род реплик совпадает с полом голоса: LLM получает указание говорить о себе в мужском или женском роде, шаблонные ответы без LLM написаны без родовых форм. Во встроенных сценариях «Срок отчёта с руководителем» и «Цена и объём работ с заказчиком» собеседники мужчины.
- Маскот-наставник. После «Начать» и до первого хода маскот листает наставления: сначала свои от организации (или от автора сценария), потом 2–3 стандартных по методу и одно по слабой стороне из входного теста. Во время диалога маскот сидит в углу и по клику открывает их снова.
- Подсказки по условиям. После каждого хода бэкенд проверяет условия по разметке и счётчикам, без вызовов LLM: `label:<метка>` (ход содержит метку), `missing:<метка>@N` (к ходу N метки не было), `irritation_high` (до срыва два шага раздражения), `trust_low` (доверие −3 и ниже), `readiness_high` (следующий удачный ход даст уступку), `turns_left:N`. Свои подсказки из карточки идут первыми, стандартные (3–4 на метод) работают всегда. Каждая срабатывает один раз за сессию, не больше двух за ход; при переигровке сработавшие подсказки пересчитываются по сохранённым ходам. Код: `backend/app/engine/hints.py`, `frontend/src/Coach.tsx`.
- Справочник метода. В диалоге кнопка «Метод …» открывает пошаговый справочник по SPIN, Гарвардскому методу или BATNA: суть, шаги с удачными и неудачными фразами и метками, что сбивает метод, как ходы двигают шкалы, оси судьи и расчёт балла (`frontend/src/methods.tsx`).
- Разметка без LLM (`backend/app/engine/offline.py`). Вопрос об интересах ставится только по маркерам интересов («что для вас важно», «почему», «при каких условиях»), вопрос без маркеров и других меток считается ситуационным. Риторические вопросы и упрёки («вы серьёзно?», «сколько можно») размечаются как давление. Отрицания («без проблем», «не уступим», «не понимаю») метку не дают.

## Методики

- SPIN: ситуационные, проблемные, извлекающие и направляющие вопросы.
- Гарвардский метод: люди отдельно от проблемы, интересы вместо позиций, варианты взаимной выгоды, объективные критерии.
- BATNA: пользователь сравнивает сделку со своей альтернативой, обозначает границу приемлемого, уступает только в обмен («если вы…, то мы…») и выходит из сделки, если она хуже альтернативы. Оси судьи: сравнение с альтернативой, защита границы, обмен условиями, исследование интересов. Без LLM оценка считается по счётчикам меток со штрафом за давление. Ссылка на альтернативу вместе с давлением звучит как угроза и снижает доверие собеседника. Встроенные сценарии: «Поставщик повышает цену», «Переговоры об оффере» и «Пункт о допработах в договоре».
- Свободный режим: выяснение интересов, аргументация, конкретные предложения, контроль эмоций.

Метки BATNA (сравнение с альтернативой, граница, обмен условиями, выход к альтернативе) ставятся при любом методе. Реплика с выходом к альтернативе завершает переговоры исходом «Рациональный выход к альтернативе». Разбор показывает, верно ли решение: выход верен, если позиция собеседника хуже худшего для пользователя края целевой зоны, то есть выгодной сделки не было. За верный выход очко сессии получает тот же бонус +10, что и соглашение в зоне.

Стек: FastAPI, SQLAlchemy, Postgres, LiteLLM и Instructor (любой провайдер LLM), React и Vite; голос — Yandex SpeechKit v3, 3D-собеседник — TalkingHead на three.js.

## Запуск

Нужны Python 3.12+ и Node.js 20+ (проверено на Python 3.13 и Node 24), браузер — актуальные Chrome, Firefox, Edge или Safari.

`.env` лежит в корне репозитория, рядом с `docker-compose.yml`:

```bash
cp env.example .env   # укажите LLM_MODEL и LLM_API_KEY или OFFLINE_MODE=true
```

Docker:

```bash
docker compose up --build
```

Откройте http://localhost:8000.

Без Docker нужны два терминала. Бэкенд читает `.env` и из своей папки, и из корня репозитория.

Терминал 1, бэкенд (по умолчанию SQLite в `backend/arena.db`):

```bash
cd backend
python -m venv ../.venv && ../.venv/Scripts/activate   # Linux/macOS: source ../.venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

Терминал 2, фронтенд (запросы к `/api` проксируются на порт 8000):

```bash
cd frontend
npm install
npm run dev   # http://localhost:5173
```

Тесты: `cd backend && python -m pytest`. Тесты работают в режиме без LLM на временной SQLite и не трогают `arena.db`.

### Российские модели: YandexGPT и GigaChat

Модель задаётся настройкой, код не меняется: подойдёт любая, которую поддерживает LiteLLM. Для внедрения ориентируемся на российские модели, чтобы реплики сотрудников не уходили за рубеж.

- **YandexGPT** через OpenAI-совместимый API Yandex Cloud. Сервисному аккаунту нужна роль `ai.languageModels.user`:
  ```
  LLM_MODEL=openai/gpt://<folder_id>/yandexgpt/latest
  # карточка по описанию генерируется разово, поэтому при yandexgpt-lite она сама идёт в YandexGPT Pro (или задайте LLM_CARDGEN_MODEL)
  LLM_API_BASE=https://llm.api.cloud.yandex.net/v1
  LLM_API_KEY=<API-ключ сервисного аккаунта>
  ```
- **GigaChat** — встроенный провайдер LiteLLM `gigachat/`. Ключ авторизации LiteLLM берёт из переменной окружения `GIGACHAT_CREDENTIALS`: при запуске через Docker её достаточно положить в `.env`, при локальном запуске — экспортировать в окружение.
  ```
  LLM_MODEL=gigachat/GigaChat-2-Max
  GIGACHAT_CREDENTIALS=<ключ авторизации>
  ```

С живыми ключами эти две конфигурации пока не проверены: прототип на хакатоне работает на модели из `env.example`.

`ADMIN_TOKEN` в `.env` — запасной ключ владельца площадки (поле в форме сценария): с ним можно менять любой сценарий, включая встроенные и зафиксированные. Без токена фиксировать сценарии может только администратор организации.

## Форма сценария и генерация карточки

- Кнопка «Как заполнить сценарий» открывает пошаговую справку, у каждого поля кнопка «?» раскрывает подсказку (`frontend/src/scenarioHelp.tsx`).
- Значок группы (`domain_icon`): один из 17 значков, картинки `frontend/public/illustrations/grp_<имя>.png`. «Авто» подбирает значок по словам сферы. Группа на главной берёт значок первого сценария, затем подбор по словам, затем SVG-плитку.
- Персонаж собеседника: галерея встроенных персонажей из `GET /api/avatars/characters` (`backend/app/characters.py`) и загрузка своего GLB. Клик по персонажу ставит его и голос по полу. Pixar-персонажи отдаются с `ready: false` и в галерее отмечены «скоро».
- Целевая зона двух видов (`TargetZone` в `backend/app/schemas.py`). Числом: `unit` — предмет и единица через запятую, четыре позиции в этой единице. Вариантами: `options` — 2–8 формулировок от лучшей для пользователя к худшей, `unit` — предмет торга словами, позиции — номера вариантов с нуля. Движок работает с номерами так же, как с числами: уступка — шаг на соседний вариант, соглашение в зоне и выход к альтернативе считаются по номерам. Везде, где позиция показывается людям (реплики, промпты собеседника и судьи, шкала торга, разбор), вместо номера выводится текст варианта. Без LLM вариант в реплике распознаётся по словам формулировок (`option_index` в `backend/app/engine/offline.py`). Пример — встроенный сценарий «Пункт о допработах в договоре».
- Генерация карточки (`backend/app/cardgen.py`). Инструкция собрана из блоков: общие правила, целевая зона и блок на каждое поле; из тех же блоков собраны описания полей схемы. После ответа карточка проходит проверку: мелкие огрехи прототип исправляет сам (перевёрнутые края зоны, русские названия перечислений, подпись в первой реплике, лимит ходов 6–14), остальные ошибки возвращает модели на повторную попытку. Если торг не о числе, модель заполняет `options` и номера вариантов с единицы; проверка переводит их в номера с нуля и сверяет порядок, границы и первую реплику собеседника. Если карточка так и не собралась, `POST /api/scenarios/generate` отвечает 422 с понятной причиной. Карточке назначается готовый персонаж того же пола, что и голос.
- Модель генерации: `LLM_CARDGEN_MODEL`; если пусто, основная `LLM_MODEL`, а при YandexGPT Lite — YandexGPT Pro.

## Аккаунты и организации

Вход необязателен: без него тренажёр работает в гостевом режиме. Общего списка гостевых сессий нет: история гостя — сессии, которые запомнил его браузер, а открыть сессию можно по её ссылке. После входа сессии привязываются к пользователю, история и результаты сессии видны только ему.

- Регистрация и вход по логину и паролю. Пароль хранится как PBKDF2-SHA256 с солью, токен сессии передаётся в заголовке `Authorization: Bearer`, в базе лежит только его хеш.
- Пользователь создаёт организацию и становится её администратором. Сотрудники вступают по коду приглашения в профиле, администратор может выпустить новый код.
- Администратор назначает и снимает других администраторов и удаляет участников в кабинете. Последнего администратора снять нельзя. Участник выходит из организации в профиле, единственный администратор сначала назначает преемника.
- Кабинет организации (только администратор): участники, число сессий, время тренировок (от первой до последней реплики сессии), средние оценки по осям судьи, доля соглашений в целевой зоне, лучшие за период по рейтингу и по каждой оси. Период: неделя, месяц, всё время.
- Права на сценарии. Встроенные сценарии не меняются: кнопка «Сделать копию» сохраняет настройки в новый сценарий. Открытый сценарий меняет его автор и администратор организации автора; сценарий, созданный без входа, — браузер, который его создал (сервер выдаёт ключ правки один раз). Зафиксированный сценарий принадлежит организации администратора, который его зафиксировал, и меняет его только администратор этой организации. `ADMIN_TOKEN` остаётся запасным способом. Список сценариев у каждого свой: встроенные, свои, сценарии своей организации; гость видит встроенные и созданные в его браузере.
- Старые базы не падают: новые таблицы создаются при старте, колонки `sessions.user_id`, `scenarios.org_id`, `scenarios.owner_id` и `scenarios.edit_key` и настройки медалей `orgs.medal_slots`, `orgs.gold_share`, `orgs.silver_share` добавляются `ALTER TABLE`, если их нет (SQLite и Postgres).

## Лидерборд

Как сравнивать сессии разной сложности (формула в `backend/app/scoring.py`):

- очко сессии = средняя оценка судьи по осям метода × множитель сложности (лёгкая 0,8, средняя 1,0, сложная 1,25) + 10, если соглашение в целевой зоне или верный выход к альтернативе;
- рейтинг пользователя = среднее по его 5 лучшим сессиям за период. Неудачные попытки его не снижают, число сессий само по себе очков не даёт;
- в зачёт идут сессии с разбором судьи: от LLM или по правилам, если LLM недоступна.

Лидерборд двух видов: внутри организации и общий. В общий попадают только те, кто включил это в профиле, по умолчанию выключено.

### Сезоны и медали

- У организации всегда открыт один сезон рейтинга. Рейтинг в лидерборде организации и в кабинете считается по сессиям с начала сезона; вкладка «Весь сезон» заменяет «Всё время». Первый сезон («Сезон 1») включает все сессии участников.
- Администратор задаёт в кабинете число мест с медалями и доли золота и серебра, остальные места получают бронзу. Золото = round(места × доля золота), серебро = round(места × доля серебра), бронза — остаток; при ненулевой доле золота одно золото есть всегда. Если людей с рейтингом меньше, чем мест, доли считаются от их числа. 0 мест выключает медали. По умолчанию 10 мест, 20% золота, 30% серебра.
- Лидерборд организации показывает правило и метку у верхних мест: какую медаль участник получит, если сезон закроют сейчас. У имени мелко — число медалей за прошлые сезоны.
- «Закрыть сезон» (только администратор) с двумя галочками: выдать медали и начать новый сезон. Медали выдаются по рейтингу сезона и сохраняются навсегда, их видно в профиле, в том числе после выхода из организации. За один сезон медали выдаются один раз (повтор — 409). Новый сезон начинается с текущего момента, старые сессии не удаляются. Можно выдать медали без сброса и сбросить без медалей.
- API: `GET /api/orgs/me/season`, `PUT /api/orgs/me/medals`, `POST /api/orgs/me/season/close` (`award`, `reset`, `next_name`), `GET /api/profile/medals`.

## Голос и 3D-собеседник

Игрок отвечает текстом или голосовым сообщением. Кнопка микрофона работает как в Telegram: удержание пишет, отпускание отправляет, сдвиг пальца или мыши влево отменяет запись. Короткое нажатие включает запись без удержания: «Стоп» → прослушать, удалить или отправить. Голосовое длится до 30 с. Браузер записывает звук через MediaRecorder и перекодирует его в WAV 16 кГц моно, бэкенд распознаёт речь, дальше идёт обычный ход: разметка → правила → ответ. В чате реплика помечается «голосовое», рядом плеер с исходной записью и распознанный текст.

Собеседник отвечает в одном из двух режимов, переключатель есть в диалоге, режим по умолчанию задаётся в профиле (хранится в браузере):
- «Текст»: как раньше;
- «3D и голос»: ответ озвучивается, 3D-аватар говорит с липсинком, текст остаётся в чате и дублируется субтитром. Камера TalkingHead в виде `upper` (голова и плечи), сцена портретная 4:5 на десктопе и 16:10 на телефоне; фон — комната `illustrations/bg_room.png` из CSS-переменной `--stage-image`. Реплика идёт субтитром в полосе внизу сцены, до двух строк, по предложениям синхронно с таймингами слов. Выражение лица и тон голоса зависят от состояния собеседника на этом ходу.

| Состояние на ходу | Настроение аватара | Женский голос | Мужской голос |
|---|---|---|---|
| срыв переговоров или раздражение от 60 % порога срыва | angry | jane, evil | kirill, strict |
| доверие ниже нуля и раздражение от 1 | skeptic | jane, neutral | kirill, strict |
| доверие −3 и ниже | disgust | jane, neutral | kirill, strict |
| доверие от 3 или соглашение | happy | jane, good | kirill, good |
| лимит ходов или выход к альтернативе | sad | jane, neutral, медленнее | kirill, neutral, медленнее |
| остальное | neutral | jane, neutral | kirill, neutral |

Код: `backend/app/voice.py` (провайдеры, амплуа, проверка файлов), `frontend/src/voice/` (запись), `frontend/src/avatar/` (TalkingHead и русский липсинк).

### Что выбрано и почему

- Распознавание: Yandex SpeechKit STT v3, метод `RecognizeStreaming` по gRPC. Файл уходит целиком одним потоком в режиме `FULL_DATA`, ответ приходит в том же запросе. В асинхронном v3 (`recognizeFileAsync`) документация передаёт аудио ссылкой на бакет Object Storage, а результат нужно забирать опросом; для реплики до 30 с это лишние шаги и задержка. Нормализация текста по умолчанию выключена: распознанная реплика остаётся как есть, со словами-паразитами, и судья видит живую речь. Числа при этом приходят словами; LLM-разметка их понимает, а разбор без LLM ловит только цифры. `VOICE_TEXT_NORMALIZATION=true` включает нормализацию (числа цифрами, пунктуация). Клиентский код сгенерирован из `stt.proto` репозитория yandex-cloud/cloudapi и лежит в `backend/app/yandex/`, из зависимостей нужны только `grpcio` и `protobuf`.
- Формат записи: браузер сам отдаёт WAV 16 кГц, поэтому ffmpeg на сервере не нужен. OGG/Opus бэкенд передаёт в Yandex как есть, WebM и MP3 перекодирует ffmpeg, если он установлен; без ffmpeg такие файлы получают понятную ошибку 415.
- Озвучка: Yandex SpeechKit TTS v3 `utteranceSynthesis` по REST, модель `general`: только у неё есть амплуа и тайминги слов (`word_timings`), у `livetts` таймингов нет. Лимит TTS v3 — 250 символов на запрос, поэтому бэкенд режет ответ по предложениям, склеивает PCM и сдвигает тайминги. Фронт получает WAV в base64 и тайминги слов (`POST /api/tts`), озвучка идёт отдельным запросом и не задерживает ход. Результат кэшируется в `uploads/tts_cache/`: тот же текст с тем же голосом, амплуа и скоростью синтезируется один раз.
- Аватар: TalkingHead 1.7 (MIT) на three.js, подключается динамическим импортом: код 3D грузится, только когда включён режим «3D и голос». Русского модуля липсинка в TalkingHead нет, он написан по образцу финского: буква → визема Oculus, я/е/ё/ю в начале слова и после гласной, ь, ъ дают «й» + гласную, ь и ъ отдельно не звучат, числа и знаки (%, ₽) раскрываются словами (`frontend/src/avatar/lipsync-ru.ts`).
- Если нет WebGL, 3D-модель не загрузилась или упал код 3D, диалог показывает причину и продолжается текстом.

### Без ключей Yandex

Ключей в репозитории нет. Пока `YANDEX_API_KEY` не задан:
- кнопка микрофона видна, но по нажатию пишет «Распознавание речи не настроено…», `POST /api/sessions/{id}/voice` отвечает 503 с тем же текстом;
- в режиме «3D и голос» аватар проигрывает липсинк по тексту без звука: длительность слов оценивается по числу букв, паузы по знакам препинания, текст идёт субтитром. Если ключ задан, но Yandex не ответил, происходит то же самое;
- текстовый режим работает как раньше.

Открытые модели как запасной вариант проверены и не взяты: GigaAM импортирует torch даже для ONNX-инференса, Silero TTS грузится через torch.hub, у T-one нет torch, но в зависимостях `kenlm`, который на Windows не собирается (проверено `pip install kenlm` 27.09.2026). T-one можно поднять отдельным контейнером `tinkoffcreditsystems/t-one`, в эту версию не входит.

### Как включить Yandex SpeechKit

1. В Yandex Cloud создайте сервисный аккаунт: https://yandex.cloud/ru/docs/iam/operations/sa/create
2. Назначьте ему роли `ai.speechkit-stt.user` и `ai.speechkit-tts.user` на каталог: https://yandex.cloud/ru/docs/iam/operations/sa/assign-role-for-sa
3. Создайте API-ключ сервисного аккаунта: https://yandex.cloud/ru/docs/iam/operations/authentication/manage-api-keys
4. Впишите в `.env` `YANDEX_API_KEY=<ключ>`; `YANDEX_FOLDER_ID` для ключа сервисного аккаунта можно не задавать. Перезапустите бэкенд, `GET /api/voice/status` должен вернуть `"stt": true, "tts": true`.

Если ключ не принят, ошибка в чате называет роль, которую нужно проверить.

### 3D-модель собеседника

Встроенные персонажи — четыре чиби-модели `frontend/public/avatars/chibi_b1.glb` … `chibi_b4.glb`: Ольга, Марина (женский голос), Сергей и Артур (мужской), портреты в `avatars/portraits/`. Модели сделаны в Hunyuan 3D, для них в `frontend/src/avatar/profiles.ts` заданы камера «голова и плечи», мягкий свет, тон-маппинг Neutral и дополнительное настроение `skeptic` (одна бровь вверх, другая вниз с прищуром, уголок рта вниз). Сценарий без своего аватара получает чиби по голосу: женский — Ольга (`chibi_b1`), мужской — Сергей (`chibi_b3`). Pixar-версии тех же персонажей в плане развития, в галерее они отмечены «скоро».

Запасная модель `frontend/public/avatars/mpfb.glb` — пример `mpfb.glb` из репозитория TalkingHead, сделан в Blender с MPFB, лицензия CC0 (раздел лицензий в README TalkingHead: https://github.com/met4citizen/TalkingHead). Модель сжата gltf-transform (текстуры 1024 px в WebP, геометрия Meshopt): 3 МБ вместо 37 МБ.

Остальные примеры TalkingHead (brunette, avaturn, avatarsdk, vroid) разрешены только для некоммерческого использования, поэтому в проект не взяты.

Свой аватар: в форме сценария блок «Персонаж собеседника» → «Загрузить свой GLB». Файл ложится в `backend/uploads/avatars/` (`UPLOADS_DIR`), отдаётся статикой по `/uploads/...`, ссылка сохраняется в поле `avatar_url` карточки. Сервер проверяет расширение `.glb`, сигнатуру и версию glTF 2.0, длину из заголовка, лимит размера `AVATAR_MAX_MB` (30 МБ) и наличие узлов `Armature` и `Head`; если нет визем Oculus или ARKit-блендшейпов, модель принимается с предупреждением. Голос собеседника (женский или мужской) выбирается там же.

Какой GLB подходит: скелет с именами костей Mixamo / Ready Player Me, 52 ARKit-блендшейпа и 15 визем Oculus (`viseme_aa`, `viseme_PP` …). Откуда взять:
- Avaturn (https://avaturn.me): аватар по селфи, экспорт GLB; TalkingHead пишет, что аватары Avaturn Type-2 совместимы полностью. Бесплатно для некоммерческого использования, о коммерческом нужно уведомить компанию. Документация: https://docs.avaturn.me/
- VRoid Studio (https://vroid.com/en/studio): аниме-персонаж, экспорт VRM 1.0, конвертация в GLB в Blender по инструкции TalkingHead: https://github.com/met4citizen/TalkingHead/blob/main/blender/VRoid/VROID.md
- Blender + MPFB (https://static.makehumancommunity.org/mpfb.html): параметрический человек, инструкция TalkingHead с ригом, виземами и ARKit: https://github.com/met4citizen/TalkingHead/blob/main/blender/MPFB/MPFB.md

Большую модель перед загрузкой стоит сжать (https://gltf-transform.dev/cli):

```bash
npx @gltf-transform/cli resize model.glb a.glb --width 1024 --height 1024
npx @gltf-transform/cli webp a.glb b.glb
npx @gltf-transform/cli meshopt b.glb model-small.glb
```
